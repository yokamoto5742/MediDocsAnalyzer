# 医療文書集計アプリ

## 概要
医療文書集計アプリは、医療文書担当一覧(Excel)をデータベース(SQLite)に取り込み、指定期間内の文書作成件数を担当者別・診療科別に集計して、画面の表とグラフで表示するWindows向けデスクトップツールです。集計結果はグラフ付きのExcelに出力して印刷できます。

## ✨ 主な機能
- 集計開始のたびに元データをデータベースに取り込み、元データの預り日の範囲を入れ替える(担当者の変更や行の削除も反映)
- 取り込めなかった行(日付の誤りなど)を患者IDとともに一覧で表示し、コピー・CSV保存(出力先フォルダに `取込エラー行_{yyyymmdd_HHmmss}.csv` で保存)
- 年と期間(月・四半期・上半期・下半期・一年)を選ぶだけで、分析期間を自動入力(1月始まり/4月始まりを選択可能)
- 「概要」タブ: 本日を含めて直近の数日(既定は7日)に預かった文書のうち、担当者名または医師依頼日が空の行の件数と一覧(業務の割り振りに使う)
- 「全体」タブ: 担当者×診療科の件数表(合計・診療科の見出しで並べ替え)と、担当者別の横棒グラフ
- 「個人」タブ: 担当者ごとの合計・平均・診療科別・文書名別上位10件・月別グラフ
- 全体・個人の集計をグラフ付きのExcel(A4横1枚)に出力して印刷
- 担当者・診療科のマスタ編集
- 起動時に1日1回データベースをバックアップ(世代数を設定可能)
- 電子カルテIDとパスワードによるログイン(管理者・職員の2つの権限)

## 動作要件
- Windows OS
- Python 3.13以上
- [uv](https://docs.astral.sh/uv/)
- 依存パッケージ(詳細は `pyproject.toml` を参照): babel, matplotlib, openpyxl, tkcalendar

## インストール方法
1. リポジトリをクローンまたはダウンロードします
2. プロジェクトフォルダで依存パッケージをインストールします
   ```bash
   uv sync
   ```
3. `utils/config.ini` の `[PATHS]` セクションを環境に合わせて設定します(起動後に「設定」ボタンからも設定できます)

## 使用方法
アプリケーションを起動します。
```bash
uv run python main.py
```

1. 初めて使うときは、「Excel読込」ボタンで旧データベース(xlsx)をデータベースに取り込みます。入れ替える範囲と件数を確認してから取り込みます
2. 「年」「年の始まり(1月始まり/4月始まり)」「期間」を選ぶと、開始日・終了日が自動で入ります(日付欄に `yyyy/mm/dd` 形式で直接入力することもできます)
3. 「集計開始」ボタンで、元データを取り込んでから集計し、右側の「全体」「個人」タブに結果が表示されます(「概要」タブは起動時と集計開始のときに元データから更新されます)
4. 印刷するときは、各タブの「Excel出力」ボタンで出力先フォルダにExcelを保存します。開いたフォルダからExcelを開いて印刷します

| ボタン | 動作 |
|---|---|
| 集計開始 | 元データ(xlsm)を確認なしで取り込み、入力された期間で集計して画面に表示します。取り込めなかった行があれば一覧を表示します。期間は次回起動時に復元されます |
| マスタ設定 | 担当者(氏名・表示順・在籍・電子カルテID・権限)と診療科を編集し、仮パスワードを発行します |
| Excel読込 | 旧データベース(xlsx)をデータベースに取り込みます。取り込めなかった行があれば一覧を表示します |
| 設定 | ファイルパス(元データ・データベース・旧データベース・バックアップ先・出力書式・出力先)と、画面の幅・高さ、バックアップの保存世代数、概要で確認する日数を変更します。数値は範囲内の整数だけを保存します |
| パスワード変更 | ログイン中の利用者のパスワードを変更します(ログインしたときだけ表示) |
| 閉じる | アプリを終了します |

## ログインと権限
- 最初はログインなしで起動し、すべての操作ができます
- マスタ画面で管理者に電子カルテIDを登録し、「仮パスワード発行」を押すと、次回の起動からログインが必要になります
- 仮パスワードでログインすると、新しいパスワード(6文字以上)への変更を求めます
- 職員は集計開始(元データの取り込みを含む)と、概要タブ・自分の個人集計の表示とExcel出力だけができます。マスタ設定・Excel読込・設定は使えません
- データベースを開けないときは、「設定」でファイルパスを直せるようログインなしで起動します

## 入力ファイルの形式
- 1行目が見出し、2行目以降がデータです。見出し名で列を探すので、列の順番や余分な列は問いません
- 必要な列: `預り日`、`患者ID`、`文書名`、`診療科`、`医師名`、`担当者名`、`医師依頼日`
- 日付は日付型・Excelのシリアル値・`yyyy/mm/dd` 形式の文字列のどれでも読み込めます
- 患者名・備考は取り込みません

## データ処理の流れ
1. 取り込み(集計開始の元データ、Excel読込の旧データベース)
   - 読んだファイルの預り日の最も古い日から最も新しい日までにある文書を、データベースから消してファイルの内容で入れ直します。範囲外の文書は残ります
   - 医師依頼日または担当者名が空の行は下書きとして取り込みません
   - 日付が読めない行、医師依頼日が預り日より前の行、マスタにない担当者名の行は取り込まずに一覧に出します
2. 集計開始
   - 元データを取り込んだあと、データベースから預り日が期間内(両端を含む)の文書を集計します
   - 全体の表は「合計」や診療科の見出しを押すと並べ替えます。もう一度押すと昇順と降順が切り替わります。合計行はいつも一番下です
   - 退職にした担当者は、期間内に件数があるときだけ表示します
3. 概要
   - 起動時と集計開始のときに元データを読み、預り日が本日を含めて `pending_days` 日以内の下書き(担当者名または医師依頼日が空の行)を、預り日の新しい順に表示します。データベースには保存しません
   - 起動時に元データを読めないときは、エラーを概要タブの見出しに表示します
4. バックアップ
   - 起動時にその日のバックアップがなければ `backup_dir` に `{データベース名}_{yyyymmdd}.db` を作り、`keep_generations` を超えた古いものを削除します

## 設定ファイル
設定は `utils/config.ini` の1つだけです。ビルドした exe では、exe と同じフォルダの `config.ini` を使います(無ければ同梱のものをコピーします)。`[Appearance]`・`[PATHS]`・`[Backup]`・`[Overview]` は「設定」画面で変更します。`[Analysis]` はメイン画面とマスタで決まるため、設定画面には出しません。

| セクション | キー | 内容 |
|---|---|---|
| `[Appearance]` | `window_width` / `window_height` | ウィンドウの幅・高さ(px) |
| `[PATHS]` | `source_file_path` | 元データ(医療文書担当一覧)のパス |
| | `database_path` | データベース(SQLite)のパス。共有フォルダに置けます |
| | `legacy_database_path` | 旧データベース(xlsx)のパス。「Excel読込」で使います |
| | `backup_dir` | データベースのバックアップ先フォルダ |
| | `template_path` | 全体の出力書式(テンプレートExcel)のパス |
| | `output_dir` | 集計結果の出力先フォルダ |
| `[Backup]` | `keep_generations` | 残すバックアップの数(既定は30) |
| `[Overview]` | `pending_days` | 概要で確認する日数(本日を含む。既定は7) |
| `[Analysis]` | `start_date` / `end_date` | 前回の分析期間(アプリが自動で更新) |
| | `year_start_month` | 年の始まりの月(1 または 4)(アプリが自動で更新) |
| | `ordered_names` | マスタが空のときに登録する担当者(カンマ区切り) |
| | `clinical_departments` | マスタが空のときに登録する診療科(カンマ区切り。`合計` は除いて登録) |

## 集計結果のExcel
### 全体
- A1: `医療文書作成件数 {最初の預り日}-{最後の預り日}`
- 2行目: `氏名`、`合計`、マスタの診療科
- 3行目以降: 担当者ごとの件数。`合計` 列はマスタの診療科の合計
- 最終行: 診療科ごとの合計。`合計` 列は一覧にない担当者・診療科も含めた全体の件数
- 表の下に担当者別の積み上げ横棒グラフ
- ファイル名: `医療文書作成件数{最初の預り日}-{最後の預り日}.xlsx`

### 個人
- 合計と担当者1人あたりの平均、診療科別・文書名別(上位10件)・月別の件数、月別グラフ
- ファイル名: `医療文書作成件数_{氏名}_{開始日}-{終了日}.xlsx`

├── main.py                               # エントリーポイント(ログイン後にメイン画面を表示)

│   ├── app_window.py                     # メイン画面(MedicalDocsAnalyzerGUI)

│   ├── charts.py                         # matplotlib のグラフ
│   ├── login_dialog.py                   # ログイン・パスワード変更

## 開発者向け情報
### 開発コマンド
```bash
uv run pyright                       # 型チェック
uv run pytest tests/ -v --tb=short  # テスト(全件)
uv run python build.py               # exe のビルド
```

### データフロー
1. `main.py` がログインの要否を確かめ、必要ならログイン画面を出してから `MedicalDocsAnalyzerGUI` を表示する
2. `MedicalDocsAnalyzerGUI` がユーザー入力を受け取り、`MedicalDocsAnalyzer` の `prepare_source_import` / `prepare_legacy_import` / `apply_import` / `overall_summary` / `staff_summary` / `run_analysis` / `export_staff` を呼び出す
3. `MedicalDocsAnalyzer` が設定を読み込み、`service_excel_reader` で読み込み、`service_database` に書き、`service_data_analyzer` で集計する
4. `service_excel_writer` が集計結果をExcelに書き出し、出力先フォルダを開く

## トラブルシューティング
1. 「取り込むファイルにデータがありません。」と表示される
   - 「設定」で元データ・旧データベースのパスが正しいか確認
2. 「取り込めなかった行」が表示される
   - 一覧の行番号・患者IDを元データで確認して直し、もう一度取り込む。担当者名がマスタにない場合は、マスタに登録
3. 「指定された期間内のデータがありません。」と表示される
   - 元データの期間外なら、先に「Excel読込」で旧データベースを取り込んだか確認
4. Excelが保存できない
   - 同名の結果ファイルをExcelで開いたままだと保存できないため、閉じてから再実行
5. ログインできない
   - 管理者がマスタ画面で仮パスワードを発行し直す
