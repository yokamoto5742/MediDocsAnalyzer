# 医療文書集計アプリ

## 概要
医療文書集計アプリは、別のアプリ CSV2XL が作る医療文書担当一覧のデータベースを読み、指定期間内の文書作成件数を担当者別・診療科別に集計して、画面の表とグラフで表示するWindows向けデスクトップツールです。集計結果はExcel(テンプレートに件数を入れ、グラフはテンプレートが描く)に出力して印刷できます。文書の取り込みとデータベースのバックアップは CSV2XL が行い、このアプリは文書のデータベースを読むだけです。

## ✨ 主な機能
- CSV2XL の文書データベースを読み取り専用で開き、集計のたびに最新の内容を集計
- 年と期間(月・四半期・上半期・下半期・一年)を選ぶだけで、分析期間を自動入力(1月始まり/4月始まりを選択可能)
- 「概要」タブ: 本日を含めて直近の数日(既定は7日)に預かった文書のうち、担当者名または医師依頼日が空の行の件数と一覧(業務の割り振りに使う)
- 集計対象(全書類・医療文書・主治医意見書)を選んで集計(全体・個人・全体推移・個人推移の各タブとExcel出力に反映)
- 「全体」タブ: 担当者×診療科の件数表(合計・診療科の見出しで並べ替え)と、担当者別の横棒グラフ
- 「個人」タブ: 担当者ごとの合計・診療科別・文書名別(全件をスクロールで表示)の表
- 「全体推移」「個人推移」タブ: 医師依頼日の月別件数を年(年度)ごとの表と折れ線グラフで表示し、Excelに出力
- 全体・個人・推移の集計をExcelに出力して印刷
- ログイン(端末ごとに有効・無効を設定)と、管理者・職員の権限(職員に見せるタブも設定可能)

## 動作要件
- Windows OS
- Python 3.13以上
- [uv](https://docs.astral.sh/uv/)
- 依存パッケージ(詳細は `pyproject.toml` を参照): babel, matplotlib, openpyxl, tkcalendar
- CSV2XL が作る文書データベース(既定は `C:\Shinseikai\CSV2XL\医療文書担当一覧.db`)
- Excel出力のテンプレート(既定は `C:\Shinseikai\MediDocsAnalyzer\template` の `医療文書作成件数.xlsx`・`医療文書作成件数推移.xlsx`)

## インストール方法
1. リポジトリをクローンまたはダウンロードします
2. プロジェクトフォルダで依存パッケージをインストールします
   ```bash
   uv sync
   ```
3. `utils/config.ini` の `[PATHS]` セクションを環境に合わせて設定します(起動後に「設定」ボタンからも設定できます)

## 使用方法
アプリケーションを起動します。
```bash
uv run python main.py
```

1. 「年」「年の始まり(1月始まり/4月始まり)」「期間」を選ぶと、開始日・終了日が自動で入ります(日付欄に `yyyy/mm/dd` 形式で直接入力することもできます)
2. 「集計対象」で全書類・医療文書・主治医意見書のどれを数えるかを選びます(初期値は全書類。次回起動時は最後に集計した項目)
3. 「集計開始」ボタンで、文書データベースの今の内容を集計し、右側の「全体」「個人」タブに結果が表示されます(「概要」タブも読み直します)。「全体推移」「個人推移」タブは、範囲・診療科・氏名を選ぶと表示されます
4. 印刷するときは、各タブの「Excel出力」ボタンで出力先フォルダにExcelを保存します。開いたフォルダからExcelを開いて印刷します

| ボタン     | 動作                                                                                                                       |
| ------- | ------------------------------------------------------------------------------------------------------------------------ |
| 集計開始    | 文書データベースから、入力された期間で集計して画面に表示し、概要も読み直します。期間は次回起動時に復元され、起動時にもこの期間で自動で集計します |
| マスタ設定   | 担当者(氏名・表示順・在籍・電子カルテID・権限)と診療科を編集し、仮パスワードを発行します                                                                           |
| 設定      | ファイルパス(文書データベース・マスタのデータベース・出力先・テンプレートのフォルダ)と、画面の幅・高さ、概要で確認する日数、個人のExcel出力の文字の大きさを変更します。数値は範囲内の整数だけを保存します                |
| パスワード変更 | ログイン中の利用者のパスワードを変更します(ログインしたときだけ表示)                                                                                      |
| 閉じる     | アプリを終了します                                                                                                                |

## ログインと権限
- ログインを使うかは端末ごとに `config.ini` の `[Login] enabled` で決めます。`false` の端末はログインなしで起動し、すべての画面と操作を使えます
- `enabled = true`(既定)でも、最初はログインなしで起動し、すべての操作ができます。マスタ画面で管理者に電子カルテIDを登録し、「仮パスワード発行」を押すと、次回の起動からログインが必要になります
- 仮パスワードでログインすると、新しいパスワード(6文字以上)への変更を求めます
- 権限はマスタ画面の担当者の「権限」(管理者・職員)で決めます。管理者はすべての画面と操作を使えます
- 職員は `[Login] staff_tabs` に並べたタブ(既定は概要・全体推移・個人・個人推移)だけを見られます。個人・個人推移は自分の分だけで、氏名を選び直せません。集計開始とExcel出力はできますが、マスタ設定・設定は使えません
- マスタのデータベースを開けないときは、「設定」でファイルパスを直せるようログインなしで起動します
- `config.ini` は端末ごとのファイルです。ログインを無効にすると誰でもすべてを見られるため、ファイルを書き換えられる人は運用で管理してください

## データベース
- 文書データベース(`documents_database_path`): CSV2XL が作る SQLite。このアプリは読み取り専用で開き、書き込みません。無いファイルは作りません
  - 集計する文書は、論理削除されていない(`deleted = 0`)行のうち、担当者名と医師依頼日の両方がある行です
  - 担当者名または医師依頼日が空の行は下書きとして、概要タブにだけ出します
  - 医師依頼日が預り日より前の行や、担当者名のリストにない担当者名は、CSV2XL が取り込むときにはじきます
- マスタのデータベース(`database_path`): 担当者・診療科のマスタとログイン情報。旧版で取り込んでいた文書のテーブルは、v2.0.0 で開いたときに削除します
- 担当者名は CSV2XL の担当者名のリストと、このアプリのマスタの両方に登録してください。全体の表に並ぶのはマスタの担当者・診療科だけです(合計行の合計には、マスタにない担当者・診療科の件数も含みます)

## データ処理の流れ
1. 集計開始
   - 文書データベースから預り日が期間内(両端を含む)の文書を集計します
   - 全体の表は「合計」や診療科の見出しを押すと並べ替えます。もう一度押すと昇順と降順が切り替わります。合計行はいつも一番下です
   - 退職にした担当者は、期間内に件数があるときだけ表示します
   - 集計対象の「主治医意見書」は文書名に「主治医意見書」を含む文書、「医療文書」はそれ以外の文書です(医療文書と主治医意見書の件数を足すと全書類の件数になります)。集計対象を選び直すと、全体・個人(集計済みのとき)と全体推移・個人推移を集計し直します。Excel出力の見出しとファイル名にも集計対象を入れます
2. 概要
   - 起動時・集計開始・設定の保存後に文書データベースを読み、預り日が本日を含めて `pending_days` 日以内の下書き(担当者名または医師依頼日が空の行。両方空は「未着手」、医師依頼日だけ空は「未完了」、担当者名だけ空は「担当不明」)を、預り日の新しい順に表示します
   - 文書データベースを読めないときは、エラーを概要タブの見出しに表示します
3. 出力フォルダの掃除・ログ
   - 起動時に `output_dir` 内で更新から `retention_days` 日を過ぎたファイルを削除します(サブフォルダは残します)
   - ログは `config.ini` と同じフォルダの `log_directory` に出し、`log_retention_days` 日を過ぎたものを削除します
4. 推移(全体推移・個人推移)
   - 文書データベースから医師依頼日が範囲内(開始日〜終了日)の文書を月別に数えます。範囲は左側の分析期間とは連動しません
   - 本日より後の月と範囲外の月は空欄にし、0件の月は線を引きません

## 設定ファイル
設定は `utils/config.ini` の1つだけです。ビルドした exe では、exe と同じフォルダの `config.ini` を使います(無ければ同梱のものをコピーします)。`[Appearance]`・`[PATHS]`・`[Overview]`・`[Excel]` は「設定」画面で変更します。`[Analysis]`・`[Trend]`・`[StaffTrend]` はメイン画面などで決まるため、設定画面には出しません。`[Login]` も設定画面には出さず、ファイルを直接書き換えます。

| セクション | キー | 内容 |
|---|---|---|
| `[Appearance]` | `window_width` / `window_height` | ウィンドウの幅・高さ(px) |
| `[PATHS]` | `documents_database_path` | CSV2XL の文書データベースのパス(既定は `C:\Shinseikai\CSV2XL\医療文書担当一覧.db`) |
| | `database_path` | マスタのデータベース(SQLite)のパス。共有フォルダに置けます |
| | `output_dir` | 集計結果の出力先フォルダ |
| | `template_dir` | Excel出力のテンプレートのフォルダ(既定は `C:\Shinseikai\MediDocsAnalyzer\template`) |
| `[Overview]` | `pending_days` | 概要で確認する日数(本日を含む。既定は7) |
| `[Excel]` | `staff_font_size` | 個人のExcel出力の表の文字の大きさ(既定は12) |
| `[Login]` | `enabled` | ログインを使うか(既定は true)。false の端末はログインなしですべてを見られます |
| | `staff_tabs` | 職員に見せるタブ(`概要`・`全体`・`全体推移`・`個人`・`個人推移` をカンマ区切り。既定は `概要,全体推移,個人,個人推移`) |
| `[FileCleanup]` | `enabled` | 起動時に出力フォルダの古いファイルを削除するか(既定は true) |
| | `retention_days` | 出力ファイルを残す日数(既定は1) |
| `[LOGGING]` | `log_directory` | ログの出力先フォルダ(`config.ini` と同じフォルダからの相対パス) |
| | `log_retention_days` | ログを残す日数(既定は7) |
| `[Analysis]` | `start_date` / `end_date` | 前回の分析期間(アプリが自動で更新) |
| | `year_start_month` | 年の始まりの月(1 または 4)(アプリが自動で更新) |
| | `document_type` | 前回の集計対象(`全書類`・`医療文書`・`主治医意見書`。無い・不正なら全書類)(アプリが自動で更新) |
| | `ordered_names` | マスタが空のときに登録する担当者(カンマ区切り) |
| | `clinical_departments` | マスタが空のときに登録する診療科(カンマ区切り。旧版の設定に残る `合計` は除いて登録) |
| `[Trend]` | `start_date` / `end_date` / `department` | 全体推移の前回の範囲・診療科(アプリが自動で更新) |
| `[StaffTrend]` | `start_date` / `end_date` / `department` / `staff_name` | 個人推移の前回の範囲・診療科・氏名(アプリが自動で更新) |

旧版の設定ファイルに残る `source_dir`・`legacy_database_path`・`backup_dir`・`[Backup]` は使いません。

## 集計結果のExcel
全体・推移はテンプレート(`template_dir`)を使います。先頭のシートの表に件数だけを入れ、グラフはテンプレートのグラフシート(Excelで作ったもの)が描きます。テンプレートが無いときはエラーのメッセージを出します。

### 全体(`医療文書作成件数.xlsx`)
- 2行目が見出し、3行目から A 列の氏名で行を探して件数を入れます。テンプレートに無い担当者・診療科は出しません
- A1 の `{集計対象}` などを置き換えた表題を、ファイル名にも使います

### 個人
- テンプレートを使わずアプリが作ります(グラフなし)
- 合計、診療科別・文書名別(上位10件)の件数。表の文字の大きさは `[Excel] staff_font_size`
- ファイル名: `医療文書作成件数_{氏名}_{集計対象}_{開始日}-{終了日}.xlsx`

### 推移(全体推移・個人推移。`医療文書作成件数推移.xlsx`)
- A 列の年の行に月別件数を入れます。テンプレートに無い年は出しません
- 月の見出しと年の名前を、年の始まりの月(1月/4月)に合わせて書き換えます。0件の月は空欄にします
- 表題とファイル名はテンプレートの A1 の形(`医療文書作成件数推移_{氏名}_{集計対象}_{診療科}_{対象期間}` など)です。全体推移では氏名を省きます

## 開発者向け情報
### 開発コマンド
```bash
uv run pyright                       # 型チェック
uv run pytest tests/ -v --tb=short  # テスト(全件)
uv run python build.py               # exe のビルド
```

`tests/fixtures/source_golden.json` は CSV2XL の文書データベースの行と、その集計・概要の見本です。集計や概要を変えたら更新してください。テスト用の文書データベースは `tests/documents_database.py` で作ります(スキーマは CSV2XL の `services/schema.sql` の写し)。テストは一時的な ini に差し替えるため、本物の `utils/config.ini` は書き換えません。

### データフロー
1. `main.py` が出力フォルダを掃除し、ログインの要否(`[Login] enabled` とマスタの管理者)を確かめてから `MedicalDocsAnalyzerGUI` を作って `start()` を呼ぶ
2. `MedicalDocsAnalyzerGUI` がユーザー入力を受け取り、`MedicalDocsAnalyzer` の `load_overview` / `overall_summary` / `staff_summary` / `run_analysis` / `export_staff` / `trend_summary` / `export_trend` を呼び出す
3. `MedicalDocsAnalyzer` が設定を読み込み、`service_database.open_documents` で文書データベースを読み取り専用で開き、`service_data_analyzer` で集計する。担当者・診療科はマスタのデータベースから読む
4. `service_excel_writer` が集計結果をExcelに保存してそのパスを返し、`app/folder.py` の `open_folder_of` が出力先フォルダを開く

## トラブルシューティング
1. 概要タブに「文書データベース(CSV2XL)を読めませんでした」と表示される、または集計でエラーになる
   - 「設定」で文書データベースのパスが正しいか、共有フォルダにつながっているか確認
2. 「指定された期間内のデータがありません。」と表示される
   - CSV2XL でその期間の CSV を取り込んだか確認
3. 担当者が全体の表に出ない
   - マスタ設定にその担当者が登録され、在籍になっているか確認
4. Excelが保存できない
   - 同名の結果ファイルをExcelで開いたままだと保存できないため、閉じてから再実行
5. ログインできない
   - 管理者がマスタ画面で仮パスワードを発行し直す
   - 管理者がだれもログインできないときは、その端末の `config.ini` で `[Login] enabled = false` にして起動し、マスタ画面で直す
6. Excel出力で「テンプレートが見つかりません」と表示される
   - 「設定」でテンプレートのフォルダが正しいか、`医療文書作成件数.xlsx`・`医療文書作成件数推移.xlsx` があるか確認
